《写代码快十倍，看懂代码少十倍：Datadog 创始人谈 AI 时代的新机会》

Datadog 这个名字，来自一台叫 Datadog 17 的 Oracle 数据库。它每六个月容量就得翻一倍，一刻不能宕机，全公司活在它的阴影里。创始人 Olivier Pomel 说，那是「痛苦的名字，旧世界的名字」。后来他们拿它当了新产品的代号，叫着叫着所有人都记住了，索性留下，只去掉 17，免得像个 MySpace 用户名。设计师在一堆阿尔法犬、猎犬的 logo 提案里递来一只小狗，Pomel 回头看，这是公司做过的最聪明的品牌决定。

十几年后，这家以噩梦数据库命名的公司年化收入逼近 20 亿美元，客户 26,000 家，最重的客户一年付费超过 1000 万美元。2023 年 6 月上线的这期 No Priors 里，主持人 Sarah Guo 和 Elad Gil 请这位从 VLC 播放器早期作者一路做到上市公司 CEO 的法国工程师，聊了聊 AI 浪潮里可观测性这门生意的走向。

起点跟监控无关，甚至跟云无关

Pomel 是工程师，小时候在欧洲追 Demo Scene，玩实时 3D，后来成了 VLC 播放器最早的作者之一。他自嘲这个播放器主要用来放盗版视频，也大方承认，让它真正成功的都是他离开后接手的人。1999 年他从法国来美国，原计划待六个月，一待就是二十多年。

泡沫破裂前后，他在纽约一家给学校做 SaaS 的教育软件公司待了八年，在那里遇到后来的 Datadog 联合创始人 Alexis Lê-Quôc。他管开发，Alexis 管运维。两人从 IBM 时代就认识，招人时刻意避开混蛋，团队氛围不算差，但开发和运维照样天天互相甩锅，大吵大闹。

Datadog 的起点跟监控无关，一开始甚至跟云无关，真正的起点是让开发和运维看到同一个世界。给他们一个平台，一个能一起干活、对齐认知的地方。

留在纽约创业，当年在投资人眼里近乎自毁。Pomel 回忆，坚持待在纽约，会被大多数投资人「当成某种精神缺陷」。融资因此更难，结果反而逼出了好处：怕融不到钱，就拼命把产品做对，公司从第一天就讲究效率，整个历史几乎一直徘徊在盈亏线附近。

纽约还给了两样湾区给不了的东西。第一，跳出湾区的回音壁，纽约有大量非科技公司可以卖产品，能听到真实需求，而不是一个点子在三个朋友之间转一圈，回到耳朵里显得更妙了。第二，招人难，留存高。Datadog 的用户大多是工程师，能看到客户组织里个人账号的流失情况，湾区公司工程师 18 个月流失一轮很常见。Pomel 认为这种流失速度之下，很难建成一家成功的公司。

AI 写得越快，看懂的价值越大

聊到 AI，Pomel 把机会拆成需求侧和产品侧。需求侧最顶层的推演是这样的：会有更多人写出更多应用。假设一个人的生产力提高十倍，他会写十倍的代码，但花在理解上的时间只剩十分之一，因为根本看不过来。

价值会从「写软件」大规模转移到「看懂它、守住安全、让它一直跑、坏了改好」。这正好是 Datadog 的地盘。训练和运行模型本身也吃掉大量基础设施，Datadog 同时服务着最大的 AI 提供方和最大的消费方，相关工作量已经在爆炸。

还有一个旧趋势被按了快进键。想用 AI，数据得先数字化，还得先上云。听起来像废话，Pomel 提醒，大多数公司到今天都没做到。想在本地机房搞 AI，连该买什么都不确定，技术变化太快。数字化转型和云迁移，就这样被 AI 加速了。

但他也泼了盆冷水。现在所有产品都急着加聊天框，两年后回头看，未必是用户想要的交互方式。

「你发动汽车的时候，不会想跟它玩二十个问题，你只想点火。」

新栈正在出现，但没人知道什么会留下来

过去十年，Datadog 擅长判断技术趋势：虚拟机到云实例，云实例到容器，容器到 Kubernetes，再到 serverless，每一步花一到三年完成大众化采用，赢家和杀手级应用都看得清。生成式 AI 完全不同，整个栈变得太快，所有人同时在试探所有排列组合。唯一让他意外的，是开源生态的速度：前沿模型还没人追上 OpenAI，开源模型却在许多更小、更明确的场景做到同等甚至更好。

客户的实际打法是两条腿走路：用最好的 API 模型（通常是 OpenAI）做测试和原型，同时盘算哪些功能可以拆给自训自托管的开源模型。Sarah 补充，最成熟的用户已经在问三个问题：什么时候能用最便宜的方案兜底，什么时候必须用最贵的技术，怎么给具体的 prompt 做路由。

对 Datadog 来说，新栈意味着新的监控对象：前沿 API 的输入输出和对错、向量数据库、自托管模型背后的 GPU。采集方式还是老三样，指标、追踪、日志。围绕 LLM 的新用例也在成型，但这条路他们之前只远观过：过去几年看到上百家公司做 ML Ops，很少跑出真正的牵引力，用例太散，用户是每家公司一小撮喜欢自己造轮子的数据科学家。现在不一样了，用户从一小撮数据科学家变成几乎所有开发者，他们关心的已经从造模型，变成让模型在应用里可靠地天天跑。「模型在干什么、干得对不对、随时间怎么变、应用改动有没有让它变好」，这组问题很可能撑起新品类。

支撑这一切的是统一平台。Datadog 内部大约一半团队做平台，一半做具体产品。内部团队往前看市场要去哪，卖的东西往后对齐客户习惯的十几个老品类，两边错位推进。Pomel 举例，可观测性正在变成一个超级品类，吞掉基础设施监控、APM、日志管理，今天还分开卖，五年十年后可能没人再把它们当三个品类。

平台扩张的节奏也有讲究。第一个产品做了六七年，一来需求追不上，二来赶上了云迁移带来的换栈窗口，市场粘性极强，客户自己长，Datadog 跟着长。后来做 APM，起因是看到客户在 Datadog 上搭简陋版的 APM，产品开放性够，客户能自己脚本化拼出来。客户肯费劲造的东西，就值得正式做出来。而真正的秘密武器是接触面：部署在客户每一台服务器上，每天被每个工程师摸一遍。

收购方法论也值得抄。签字打款是最容易的部分，难的是之后。他们的规矩：收购必须对应想做的产品方向，能换来两三年先发优势才出手；被收购的公司第一年要整体重建到统一平台上（比如 Sarah 当过董事的 Sqreen），是笔额外开销，换来的是端到端集成；只选还想留下干活的创始人。

「创始人累了想卖公司，是个卖的好理由，但对我们来说不是买的好理由。」

交割后三个月内，两边必须一起上线点东西。上什么不重要，上线本身重要。这一招逼所有人找到协作方式，让被收购方快速展示价值。Pomel 点破了收购最大的风险：收购款打水漂还算小事，老员工寒心才是大事，凭什么给新人那么多钱。

ChatGPT 调试代码，有问必答，大半是错的

这是全期最实用的一段。工程师在生产环境看到报错，手边开着 ChatGPT，第一反应是把堆栈贴进去问。Pomel 的观察：ChatGPT 百分之百会给你一个答案，问题是大半情况下答案是错的。原因很正当，没有程序状态，它不可能知道。

把堆栈和程序状态，也就是出错那一刻各变量的值，一起喂给模型，几乎每次都能拿到非常精确的答案。至少短期内，魔法来自把语言模型和其他数据源、传统数值模型组合起来。

传统方法也没有过时。Datadog 的 Watchdog 盯着所有指标找统计偏差，这类活儿传统数值方法干得极好，比 LLM 精确得多。Pomel 讲了个残酷的细节：问客户宁可要误报还是宁可漏报，客户都选误报；现实是同一周夜里收到两次误报，客户就直接把你关掉了。运维系统每分钟做上千次判断，错 2% 都痛得飞快，精度门槛必须极高。

LLM 打开的是另一扇门。有人把 LLM 叫作「语言计算器」，Pomel 觉得这个说法很准：把散落各处的元数据、数值模型的输出、内部 wiki 组合到一起，以前做不到，新的智能会从这里冒出来。前提还是那两个字，得对。

至于 AI SRE、自动排查故障，Pomel 说站在临界点上，但还差得远。他的检验标准：连 Google 这种环境极度统一、规模巨大的地方，自动化水平都不算高。自动驾驶的类比：Google 是全高速路，连高速路都自动化不了，别的公司更没戏，因为大多数公司的环境是罗马老城区。开车满 15 岁就能学，排查复杂生产环境的问题需要一队博士，还互相吵架。

别忘了时间尺度，节目录制时 ChatGPT 上线才半年，GPT-4 才三个月。Pomel 给这波 LLM 定的框架是火箭：点火已经完成，创新到处都在发生；明年左右可能带着真正的生产用例起飞，眼下大多数东西还停在 demo 和内测；真正的问题是需不需要第二级火箭才能入轨，这要两三年后见分晓。生成图片、写文案这类场景已经够用，因为人能轻松看出狗长了五条腿，重摇一次骰子就行。写代码、调试生产环境，错起来不明显，这是还没解决的部分。

近期能兑现的收益清单反而清楚：写作和起草已经够用；开发者生产力上，学一个新 API 从一下午翻文档变成几分钟提问；有些领域会被整体重写，比如邮件营销，当每个人都能用机器发一百万封邮件，整个渠道都得换个形状，得有人用别的方式穿过噪音。Sarah 追问是不是刚杀掉了这个渠道，Pomel 的回答是，它会变，只是得换个活法。

安全软件人人都在买，没人因此更安全

Datadog 的安全客户已经超过 5000 家，但这一步比之前任何一次产品扩张都迈得大：之前的新产品都还在可观测性这个大类里，用户和买家都是同一批人；安全意味着新用户、新买家。

他对行业的判断很直接。安全方案从来不缺，卖得极好，自上而下卖给 CISO。问题是结果不行，人人都在买安全软件，没人因此变得更安全。把一个锋利的单点方案卖给 CISO，出不来好结果；让大批开发者和运维工程师用上安全，把它铺到基础设施和应用的每一层，才有机会。

他给了一个医疗类比：现在有好药，但要起效，得每天往每个器官里注射一遍，没人做得到。Datadog 想把它做成输液，挂上就一直生效。打法靠部署广度和使用量，先不靠顶尖的销售。

从第一天就按盈利标准经营

宏观收紧的年景里，Datadog 交出 30% 的收入增速，还顺势推出云成本优化产品。Pomel 说经营方式没变过：一直按盈利标准经营，从底层把系统设计得可持续、高效，从不先跑通再优化。原因有二，当年怕融不到钱是其一，其二是坏习惯一旦养成就极难戒掉，身边反例看得够多。

微调有两处。客户买得更谨慎了，所以要重新校准判断客户价值和产品市场契合度的仪表，避免基于失真信号做错决定。同时生成式 AI 领域必须提速，内部跟团队的沟通换了说法：你们习惯花三四个季度过滤噪音、锁定正确用例，这次不行，噪音本身也是这个领域在发育的声音，接受多犯点错，跟市场一起迭代。

选人标准也没变。最好的员工是「问题的黑洞」，问题扔过去就消失。找法子很简单：跟着工作走。活儿会自动避开混日子的人，涌向真正能干的人，工作流向就是绩效地图。

还有一件反常规的事：Datadog 同时服务几个人的小团队和财富 100 强。逻辑回到起点，人是一样的，云和开源时代工具栈也统一了。十五年前创业公司用开源，大公司买 Oracle 和微软的企业级平台；今天大家都在 AWS 上用开源，上下栈是同一批组件。这带来企业软件公司少见的网络效应，对手抄产品没用，得把整个公司抄一遍。代价是商业上要两头平衡，长尾用户和年付几千万美元的大企业之间，信息不能串门：个人用户看到新闻里年付几千万美元的客户觉得离谱，大客户那边清楚这跟基础设施规模相称，算下来反而是省钱。

临走前，把节目里能直接抄的东西列一下：

  • 问 LLM 调试代码，别只贴堆栈，把出错那一刻的程序状态一起给，答案质量完全不同。
  • 别急着拆掉传统监控和统计异常检测。LLM 负责组合上下文，数值方法负责精度，两层搭配用。
  • 评估 AI 自动化的空间，先看环境是「全高速路」还是「罗马老城区」，越统一越先兑现。
  • 招人识人，跟着工作流向走，活儿涌向谁，谁就是能扛事的人。
  • 做收购或者合作，定一条硬规矩：三个月内一起上线点东西，上什么不重要。
