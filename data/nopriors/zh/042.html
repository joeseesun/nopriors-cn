《14 人训练前沿大模型，2 亿美元买算力：Imbue 拆解 AI Agent 的真正瓶颈》

一家只有十三四个人的公司，算力储备足以训练当今最大规模的模型，账上刚进账 2 亿美元，出资名单里有 NVIDIA 和 Astera Institute。

这家公司叫 Imbue，做的是会推理、会写代码的 AI Agent。2023 年 11 月，两位创始人 Kanjun Qiu 和 Josh Albrecht 做客投资人 Sarah Guo 与 Elad Gil 的播客 No Priors，从创业起源聊到技术路线，再到这笔钱怎么花。整场对话信息密度很高，下面把最值钱的部分捋出来。

先交代背景。两位创始人是在一个会议上认识的，后来干脆合租了一栋住着二十来人的大房子，一群技术人住在一起，室友里就有后来参与造 GPT-3 的人。合租和创业几乎同时发生。Kanjun 一直关心的是人的能动性，怎么让普通人对自己的生活有更多掌控权；Josh 从小痴迷 AI。两条线在同一个判断上交汇：如果 AI 能替人干活，人的掌控权自然变大。

2018 年前后，他们在运营一家叫 Sourceress 的 AI 招聘公司。用今天的话说，那就是他们的第一个 Agent：用老派 NLP 技术，自动把合适的候选人塞进招聘人员的收件箱，招聘的人不用主动去找。一个自主系统要真正运转起来，需要哪些配套，这段经历给了他们一手体感。2020 年初，他们注意到自监督学习同时在视频、图像、语言三个模态上跑通，机器学到的表征可能和人类高度相似。顺着这个判断，Imbue 的方向定下来了。

电脑需要被微观管理，Agent 卡在可靠性上

Kanjun 在访谈里说了句挺扎心的话：我们每天坐在电脑前，恰恰因为电脑自己什么都不会发生。

它不能自己做决定，每一步都得有人盯着，像操作一台满是旋钮的机床，你拨一下它动一下。她想要的未来是：你说一句话，电脑自己理解你想干嘛，然后去帮你干。今天到那个未来的距离，大约等于第一台计算器到现代电脑的距离。最早的数字计算机就是一台房间大小的计算器，干的活是算傅里叶变换。

Josh 补了一句：聊天机器人把答案丢给你，验证和执行的担子还在你肩上。AI 真正的承诺，是系统能替你完成目标，把你解放出来。

Sarah Guo 把技术分成三类：永远做不成的，比如被物理定律卡住的 Theranos；现在加把劲就能成的；还有注定会发生、只差基础设施的，比如 90 年代就有人预言了手机的全部功能。她问 Agent 属于哪类。答案有点意外：Agent 已经存在，只是待在光谱最左端。客服机器人接管部分售后流程，搞不定就转人工，里面的推理是硬编码的，换个公司就不通用。

Josh 给了两条光谱：一条从专用到通用，一条从副驾到自动驾驶。今天的 Agent 都在左端，能力每涨一截，就有一批新场景被更通用、更自主的 Agent 吃掉。没必要纠结「缺了哪项关键技术」这种二元问题。

真正卡住所有人的是可靠性。Josh 的比喻很妙：现在的模型像没有纠错机制的以太网，又像模拟计算机，信号传出去对不对，全凭运气。他聊过很多做 Agent 的创业者，抱怨最集中的就是这条：系统没法每一步都稳定输出正确结果。

Imbue 把解法打包在「推理」这个词里。这里的推理是个大筐：系统什么时候该回来问人，怎么知道自己不确定，怎么在几套行动方案里挑一条先试。Chain of Thought、Tree of Thought 这些热门技术，在他们的分类里都属于纠错手段，内部还有一批没公开的。

Kanjun 强调这个过程没有魔法：从 60% 可靠磨到 70%，再磨到 80%，靠的是增量式工作，新技术也是被这个过程逼出来的。指望训练一个巨型模型把一切塞进去然后万事大吉，这条路走不通。它只会在 Agent 流程的随机几个环节变好，这显然不符合预期。

一道乘法题，说明语言模型为什么不够

Elad Gil 问了个尖锐的问题：OpenAI 等实验室也在公开做多步推理和过程监督，凭什么认为需要一套不同的路子？

Josh 的回答里有个很硬的例子。语言模型在理论上就学不会通用的乘法算法，因为那个算法塞不进上下文窗口。加法倒是可以，训练得法几乎能拿满分，但模型学到的是模块化套路，始终学不到通用算法。想让机器真正执行通用算法，就得有一个外层循环，一步步决定下一步做什么。这是定义层面的要求，绕不过去。

他补了一句：OpenAI、Anthropic、Imbue 的人都清楚这一点，没人真觉得把一切塞进语言模型就完事。真正有意思的问题在那个外层系统怎么做：什么时候收集更多信息，什么时候承认自己没把握。这些问题的答案，现在还很初步。

媒介上，语言和代码都合适，语言本身足够压缩，处理起这些场景很省力。Kanjun 的观察是，今天的创业者其实在硬编码推理流程：遇到这类投诉就这么办，遇到那类就那么办。有了语言模型之后，代码和语言之间变成一条光谱：有时让模型决定下一步，有时一个 if 语句就够。越想要稳健、可复现的环节，就越该往代码那头挪。没见过的任务先用模糊直觉做，慢慢打磨，再固化成代码。

选代码，因为代码能打分

为什么第一个主战场选编程 Agent？理由有三个。

第一，代码能打分。测试要么通过要么没通过，函数要么对要么错。Josh 说很多团队扎堆做数学和代码推理，就是因为这里最容易评估。第二，代码是推理的一部分，理由上面刚说过。第三，代码能加速自己人。

第三点展开讲讲。Imbue 内部有个原则叫 serious use：只做那种自己每天都想用的 Agent。可靠性正是最大的拦路虎，自用产品反过来逼着团队把可靠性磨上去。他们现在自动写单元测试，自动修类型错误，招聘排期也准备交给 Agent。Kanjun 的原话是，照这个节奏，明年可能就不用招那么多招聘协调员了。

他们做了两个很有代表性的 Agent，各占光谱一头。一个叫 to-do agent，丢给它代码库里随便一个待办，它自己去完成，非常通用，但可能跑很久。另一个盯着每一个 pull request，跑 linter，发现类型错误就修，提交修复 PR，非常专用，但立竿见影，而且还能继续扩展：加单元测试、查安全漏洞、重命名变量，路子是一样的。等两边能力都变强，它们会往中间会合。更妙的是，通用 Agent 可以调用专用 Agent 当子程序：to-do agent 发现要写某个函数，先看有没有现成的子 Agent 干这个，成功率看着不错就调用，失败再自己上。那个通用推理层本身很专一，是个具体的规划器，不擅长浏览网页这些活，但系统整体因此更通用。

评估怎么做？Josh 说这是他们花时间最多的地方。拿到 Agent 的输出后，把它拆成一串问题：带测试了吗，能直接跑吗，改动是不是最小，变量名起得好不好。每个子问题都比「整体好不好」容易量化，一路拆下去，总能拆到语言模型甚至人能给出客观答案的那一层。他们先从客观题练手，再逐步攻主观题，因为后者的评估难得多。这套拆解法还能外溢到非代码任务，招聘 Agent 用的是同一套流程。Elad 补充说，他们看过很多 AI 开发工具公司，好评估闭环的形式很多：能不能编译、静态分析过不过、性能有没有提升、有没有现成样例可对照，比如做 Python 2 升 3 这种老代码迁移，检查手段都是现成的。这个领域吸引人的地方，恰恰是评估手段特别丰富。

那 Imbue 算产品公司吗？Kanjun 的回答是当然，公司就是要出产品，但技术有自己的时间窗口。今天做不出随时可用的 Agent，原因很简单，技术还没到。他们真正想造的，是一套让可靠 Agent 能被快速构建的工具和框架。

「今天写 Agent 的感觉，就像在用汇编语言写程序。这限制了能造什么样的 Agent，也限制了有几个人能造。」

2 亿美元买算力，不买人头

Elad 追问了一个创业者都关心的问题：大家用 GPT-4 做原型，跑通了就往 GPT-3.5 或微调过的开源模型上搬，全是为了省推理成本。他的直觉是，越通用越贵，要记忆，要更广的逻辑能力。

Josh 的答案很精彩：通用能力最大的用途，是生产专用能力。发现某个调用一天要打一万次、贵得肉疼，那就让 Agent 写段 Python 代码，把这个环节固化下来。他们管这个思路叫「每种能力配一个最小可行模型」。今天的 Agent 工作流已经是混搭：一部分用专用小模型，一部分用通用大模型，怎么省怎么来。

Kanjun 拿个人电脑的历史做了个类比：当年一部分人做超算，一部分人做个人电脑，最后个人电脑市场大得多，需要超算的人没几个。她怀疑 AI 也会走同样的路，大量场景会被务实的小模型吃掉，而小模型在数据上的潜力今天远没被榨干。

回到那 2 亿美元。Josh 说，其中相当大一块会拿去买算力。他们的公司观也很明确：不想做几万人的公司，想用小团队加海量算力撬动大产出。一万人的沟通成本没法想象，一百个人在房间里反而容易对齐目标。

杠杆已经见效了。内部有个超参数优化 Agent，以前研究员要手工决定学习率试多少、下一个实验跑什么，现在晚上设好去睡觉，早上回来全部优化完毕。整个公司十三四个人在训练前沿规模的大模型，其中大多数人根本不碰训练和基础设施。用他们自己的话说，这是一种 Agent 式的基础设施思路。

至于业界流传的那个说法，低于五千张 GPU 就没法竞争最前沿的推理研究，Josh 的回应很淡定：他们的算力储备足够训练当今最大规模的模型，问题是训最大的模型未必是最优的资源用法。训练正在变便宜：数据用得更省，训练跑得更稳不发散，监控工具更齐全。数据这块被探索得太少，很多效率提升会从更好的数据里来。这恰恰是他们投入很重的地方。

五年后，人人都是软件工程师

展望未来，Kanjun 给了两个时间点。一年内，邮件分类、日程安排这类 Agent 会真正能用，她认为今天的技术就够，拦着大家的只有可靠性。五年内，每个人都能用自己的话描述一个定制的研究流程，让电脑照着办，也就是真正的个性化 Agent，Elad 用这个词概括时她直接确认。

他们家招聘负责人的一句话被 Josh 反复引用：

「我们其实是一家软件开发工具公司。但未来每个人都会是软件工程师，所以每个人都会需要开发工具。」

Josh 的翻译是：Agent 这个词太技术化，它真正提供的东西，是一门用自然语言编程的语言。从命令行到图形界面再到触屏，电脑一直在变得更直观，而语言和视觉是人类最直观的媒介，让电脑听懂人话就是这条路的终点。

关于 AI 圈谈虎色变的递归自我改进，Josh 的描述意外地朴素：他们正在用写代码的 Agent 写写代码的 Agent，但现实中的自我改进没有戏剧性，它是一场每天把东西磨好一点的慢工，每天进步 1%，一年下来就是天文数字。

一旦算力能直接换成可靠的代码，游戏规则会变。Josh 说，今天大多数公司的瓶颈是招到能写健壮代码的工程师，这个瓶颈消失后，团队大小就不再是护城河。软件也会变多、变好、变得更定制。Kanjun 在做自动生成界面的小工具，表单字段刚好是你需要的那些，还能缓存复用。Josh 周末刚给自己捏了个 Midjourney 的交互界面，因为受够了在 Discord 里用手机敲提示词。他说这玩意儿代码量不大，等 Agent 会写代码了，任何人想要自己的版本，提个需求，五分钟后就有。

Sarah Guo 收尾那句话可以当注脚：我们会看到 25 个人的公司改变世界，会有更多、更定制、质量更好的软件。

明天就能用上的三件事

这场对话听着宏大，方法论却能直接搬走。

  • 把 Agent 当可靠性工程做。给你的 Agent 输出列一张问题清单：带测试吗、能直接跑吗、改动是否最小。先能测量，再谈改进，从 60% 到 80% 没有捷径，只有增量。
  • 高频环节固化成代码。原型阶段放心用最强的大模型，跑通之后，把每天重复上千次的调用写成脚本，或干脆让 Agent 自己生成，只把新情况留给大模型。
  • 挑一个自己天天会用的任务起步。一个你每天真会用到的小任务，比十个演示用的炫技 Demo 更能逼出真技术，这是 serious use 原则的反面应用。

Josh 那句话放在结尾正合适：每天进步 1%，一年后回头看，你已经走出很远。
