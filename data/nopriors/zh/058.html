《从副业项目到 700 个集成，LangChain 创始人 Harrison Chase 聊透 Agent 开发的瓶颈与机会》

2022 年 10 月，Harrison Chase 给一个 Python 项目提交了第一行代码。那时他刚决定离开上一家公司，下一步做什么还没想好，就去泡黑客松和开发者聚会，把大家玩大语言模型时反复出现的抽象，攒成了一个开源包。一个月后，ChatGPT 发布。

两年后，这个叫 LangChain 的副业项目有了 700 多个集成，撑起一家公司。还有个细节更能说明节奏有多快：随第一版发布的几个 OpenAI 模型，今年初已经全部下线。Harrison 在 No Priors 节目里说，现在去跑最初版的 LangChain，根本跑不起来，因为模型不存在了。

第一行代码比它接的第一批模型活得久。主持人 Sarah Guo 和 Elad Gil 把这位 CEO 兼联合创始人请来，聊了框架怎么在剧变里活下来、Agent 卡在哪、记忆怎么做、长上下文会不会干掉 RAG。这期信息密度很高，值得拆开讲。

一个副业项目，踩在 ChatGPT 发布前一个月

Harrison 的背景是机器学习和 MLOps。2022 年 9、10 月，他决定离职，方向未定，就去参加黑客松、泡 meetup，跟一批玩 LLM 的开发者聊。他发现大家在重复造同样的轮子，就把这些常见抽象打包成开源项目。时机好到离谱，一个月后 ChatGPT 出来，需求直接爆炸。

第一版 LangChain 其实很简陋：三个高阶实现，两个基于论文，一个基于前 GitHub CEO Nat Friedman 的爬虫 Agent NatBot，外加几个集成，最早只接了 OpenAI、Cohere 和 Hugging Face。Sarah Guo 提到，LangChain 第一次提交代码的那个月，正好是她创办 Conviction 基金的时间。那时还没有 Llama 2，没有 Mistral，开源模型的推理能力跟今天完全没法比。

今天的 LangChain 公司有两条产品线：开源包 LangChain，加上做测试、评估、监控的 LangSmith 平台。「LangChain 是什么」这个问题的答案，他自己说这几年一直在变，跟着整个生态一起变。但开源包的骨架从第一天起没大变：一层是集成，现在 700 个；一层是各种现成的链和 Agent 模板。

什么该稳，什么该变

管一个开源项目，最难的题是生态里挂着大批开发者，底下的技术却每三个月翻一次天。Harrison 的办法是把系统分成两层看。

底层相对稳定。集成偶尔要动，比如对话式模型出来时 API 接口大改，他们专门加了一层新抽象，但过去几个月整体平稳。真正下重注的是中间那层：把组件拼起来的运行时。用户从原型走向生产，最想做的是定制细节，所以他们做了 LangChain Expression Language（LCEL），又做了 LangGraph。LangGraph 处理带环路的图，因为 Agent 本质上是把 LLM 放进循环里反复跑，DAG 画不出这种结构。运行时死磕两件事：流式输出和结构化输出，这两点的重要性一直没变过。

变得最凶的是最上面那层「怎么把东西拼起来」的模式。从简单链，到复杂链，到全自动 Agent，再到受控状态机，两年换了四茬，底层运行时基本没动。框架的活儿就是把剧变挡在上层，别让它渗到下面去。

Agent 离能打还差三件事

Elad 问他，要让 Agent 真正有生产力，行业还缺什么。Harrison 给了三个答案。

第一是 UX。怎么向用户传达 Agent 能干什么、不能干什么，怎么让用户看到它在干什么、随时纠偏，全行业都没有标准答案。框架能做的是把中间步骤的观测和干预做好，甚至支持用户纠正中间步骤，剩下的得靠应用层大量试错。

第二，也是他认定的最大瓶颈：底层 LLM 的规划能力。现在能跑起来的 Agent，基本都是开发者把任务拆成一堆小组件，再把自己的领域知识灌进去，规定信息怎么在组件之间流动，因为模型自己想不明白这件事。学术界的大量论文也在绕这个坑，一类做显式规划，先规划再执行；一类做反思，做完自问「这结果对吗」。Harrison 的点评很直接：这两类研究都是在补 LLM 的短板。理论上模型应该自己知道要规划、要检查，现在还得靠外挂。

第三是工程流程。每个节点之间信息怎么流动？用少样本提示、微调，还是改指令？怎么测试每个节点，怎么对整个系统建立信心？这套工作流还在被发明，谁也没毕业。

记忆，一个他嫌太早期的领域

记忆是这期聊得最展开的话题，Harrison 把它拆成两类。

一类是系统级的程序性记忆：怎么正确用工具、怎么达成目标，跟具体是谁在用无关。他看到的有效做法是少样本提示加微调，其中少样本示例的效果特别突出。这里有条他反复强调的数据飞轮：监控应用，收集好的真实案例，把案例回填成少样本示例，再喂回应用。LangSmith 现在主推的就是这条链路。像师傅带徒弟，与其送出去重新培训（微调），不如把老师傅的操作手册（好案例）直接放在徒弟手边。

另一类是个性化记忆：记住 Harrison 喜欢足球和篮球，下次回答时照顾这个偏好。OpenAI 在 ChatGPT 里的做法是主动式，模型调用「记住这个事实」「删掉这个事实」这样的函数，自己决定记什么、忘什么。Harrison 更看好的是另一条路：被动式后台进程，安静地翻看对话、提炼洞见，供以后的对话使用。两条路各有优劣，他不下结论。

但对这个领域的整体现状，他的评价相当不客气：

记忆是一个极其早期的领域，真正有意思的工作量之少，让我挺失望的。

一堆方案，没有一个明显胜出。反过来看，这正是他眼里最值得进场的地方之一。

长上下文、微调、开源模型、换模型：四盆冷水

2024 年初，Gemini 1.5 Pro 带着百万 token 的上下文窗口出场，「RAG 要死了」的说法跟着起了一波。Harrison 一盆冷水泼过去。

长上下文确实让很多单次调用变得现实：从一份几百页的 PDF 里抽信息，或者对三五份长文档做检索，一次塞进去就行。但两件事它替代不了。一是规模，很多场景的数据量装不进任何窗口；二是迭代，Agent 要做决定、跟环境交互、拿回反馈再决定，这个循环跟窗口长短无关。链式调用和 Agent 不会消失。

评测的水分他也戳了。团队里的 Lance Martin 刚发了一个基准：大家熟悉的大海捞针测试，各家模型已经全绿，但这个测试跟真实 RAG 差得远。大海捞针是在长上下文里找一个信息点，像考试只考一道默写题；真实 RAG 要综合多个信息点再推理，是材料综述题。Lance 的测试把针的数量加多、把任务从检索改成推理，性能立刻往下掉。「全绿」的大海捞针成绩，解释不了 RAG 的真实表现。至于 RAG 的索引环节会怎么变，切分分块还要不要、是检索整篇文档还是更大的块、要不要回头用 Elasticsearch 这类传统搜索，他自己承认是全期最没把握的地方。LangChain 里那个给每篇文档建多个向量的父文档检索器，也许就是过渡形态之一。

微调是第二盆冷水。客户都在试，但真正用起来的只有一种情况：规模大到临界点，成本逼着动手。卡点有三个：数据集难攒，微调后的模型难评估，以及最实际的，改一个微调模型，比改一条提示词、换一组少样本示例难太多了。行业还在高速试错，没人愿意把自己锁死在一个难改的模型里，所以大多数人停在少样本示例这一步，不再往前走。

第三盆冷水泼给开源模型。兴趣在增加，但推理能力跟 Claude 3、GPT-4 的差距摆在那里，而 LangChain 主打的多步推理应用恰恰最吃推理。他的原话是，至少目前，开源模型还配不上 Twitter 上的热度。他自己把这归为他的「热门观点」。

换模型的流行叙事，同样挨了一盆。能不能拿着同一套提示词，在 Anthropic、Mistral、OpenAI 之间随意切换？Elad 自己也拿不准这个模式是真需求还是过渡期现象。Harrison 的判断是，这事比看起来难，主要卡在提示词，每个模型的提示词都得重写。但他认为提示词会慢慢收敛：模型越聪明，那些小怪癖越不重要；各家能力对齐后，可迁移性自然上来。OpenAI 的函数调用曾经是独门能力，现在 Mistral 和 Google 都有了，提示词就能搬了。还在拉开差距的清单上有：上下文窗口长度、多模态、提示注入防护，最后那个是企业客户真在乎的。他还给「什么时候想换模型」画了时间点：原型阶段随便试，真正的切换压力出现在走向规模化的那一刻，GPT-4 跑通了，要全量上线了，成本扛不扛得住？能不能降到 GPT-3.5？成本和延迟是这时候才变成决策变量的。

机会在应用层，在记忆里

应用形态的演变，他给了一条清晰的时间线。早期是链，按固定顺序一步步执行。2023 年春天 AutoGPT 火了，思路变成「扔进 for 循环自动跑」。而真正进入生产的，是两者中间的形态：受控的状态机，带环路的图。全自动循环像放养，状态机给流程装上了护栏和检查点，LangGraph 的设计就是被这个观察推动的。主持人补充，树搜索加上每一步的高效采样，最近也跑出了一批效果很好的应用，Cognition 的 Devin 演示是例子。Harrison 接话说那个演示确实惊艳，团队把「AI 干活时人怎么参与」这个交互问题答好了，这是他最兴奋的一点。

Sarah 问生态里的应用是不是明显变复杂了。Harrison 说方向对得上，市场确实在往多步 RAG、更精细的排序走，但 LangChain 从第一天就只做这类应用，他自己感受没那么剧烈。真正的新东西在 RAG 内部：查询分析开始普及。用户的问题不再直接丢给 embedding 模型，先做一轮分析，决定发给哪个检索器、搜哪段内容、要不要加元数据过滤。检索从单步变成了多步流程，跟少样本提示和数据飞轮配合着用。

哪些场景的 Agent 已经能干活？他点了三个。客服最顺理成章，Bret Taylor 创办的 Sierra 跑得不错，Klarna 二月公布的 AI 客服一个月干了相当于 700 名全职客服的活。写代码是第二个，反馈闭环天然存在：代码跑一下，行不行立刻知道，而且造工具的人自己就是开发者，能亲自测。第三个是推荐型聊天机器人，跟客服分开算，客服要解决工单，推荐要懂用户偏好，后者刚有苗头。

聊到没人做但该做的事，他的答案不在模型层。最让人兴奋的机会在应用层和 UX 层。如果今天不干 LangChain、重新创业，他会去应用层做一家公司，核心卖点就是长期个性化记忆。工具不缺，缺的是一个认真围绕记忆设计的应用和交互。

他还提到斯坦福的 DSPy 项目，认为它跟 LangChain 加 LangSmith 的思路殊途同归：把应用看成多步流程，用少样本示例去优化每一步，他接下来可能就跟 DSPy 作者 Omar Khattab 做场联合研讨。他想象的下一步是持续学习，把优化搬到线上：没有标准答案，就用环境反馈，点赞点踩，让应用自己越用越准。落到体验上，就是一个通用应用慢慢学会为不同的人做不同的事，比如为 Sarah 和为 Elad 用不同的方式搜网页。

这期节目听完，有几件事开发者明天就能动手。

  • 先建少样本示例库，别急着微调。把生产环境里的好案例收集起来，回填成少样本示例。比微调便宜，比手改提示词稳，还能随业务快速迭代。
  • 给每个 LLM 节点建评估。Agent 出问题多半出在某个具体节点上，没有节点级的测试和监控，调优全靠猜。
  • Agent 架构选受控状态机，慎用全自动循环。把领域知识写进信息流的设计里，等模型规划能力真上来了再放手。
  • 评估 RAG 别只看大海捞针。多放几根针，再要求推理，测出来的数字才接近真实业务。

两年前那个在黑客松里找方向的人，如今管着 700 个集成的生态。他给后来者的建议朴素得不像技术圈的话：别都挤去卷模型，应用层的机会大把，把记忆和持续学习当回事，让应用自己越用越好。
