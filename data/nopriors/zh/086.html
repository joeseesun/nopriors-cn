《一半AI用例在跑RAG，微调几乎没人用：Braintrust CEO讲透一线公司的真实打法》

2024年10月，AI 评测平台 Braintrust 刚从 a16z 等机构手里拿到3600万美元融资。它的客户名单读起来像一份 AI 应用头部榜单：Notion、Airtable、Instacart、Zapier、Vercel，全是第一批把 AI 塞进正经产品的公司。

CEO Ankur Goyal 做客 Sarah Guo 和 Elad Gil 的播客 No Priors。他手里有一份别人很难拿到的数据：这批公司上了生产环境的技术栈，到底长什么样。

他给出的答案，和推特上讨论了两年的热点是两回事：RAG 是绝对主流，微调几乎全军撤退。Ankur 坦白，创业时他以为人人都要微调，把它排进第一批功能规划，结果客户用脚投了票。

同一个问题做了两遍，他才敢创业

Ankur 是第三次创业。他在数据库公司 SingleStore（前身 MemSQL）早期加入，做到工程副总裁，后来创办 AI 公司 Impira 做文档提取，2022 年被 Figma 收购。

2017 年创办 Impira 的时候，LLM 这个词还不存在。他的回忆是，那时候把一个能用的 AI 产品做出来就很难，团队只好自己造工具：评测输出、收集真实用户数据、再拿数据改进评测。

被 Figma 收购之后，他以为进入了新世界。结果发现，LLM 时代的 Figma 遇到的问题和 Impira 一模一样，最后造出来的工具也差不多。

这件事让他下了决心。前 LLM 时代就存在的问题，大概率在 LLM 时代会继续存在很久。同一套工具做了两遍，需求真实到不需要再论证。

他拿着早期想法去找 Zapier 的 Brian 和 Mike、Notion 的 Simon 这些人聊。做了这么多年用户访谈，他说从没见过一个想法像这样引起共鸣，所有人都想要一个像样的评测方案。第一版原型，用他自己的话说做得挺烂，但有人开始用。一年多时间，Braintrust 靠用户的反馈、抱怨和点子迭代成了今天的样子。

商业模式上有个耐人寻味的细节。Sarah 回忆，他们本来打算把项目开源，结果第一批客户电话打进来，说的全是“别开源”。用户主动要求付钱，要求这个东西能长期存在。这种市场拉力，在开发者工具里很少见。

为什么评测这么重要？Ankur 的解释很实在。

“评测听起来真简单，不就是个 for 循环嘛，跑的时候把结果打印出来看看。但现实是，你评测跑得越快、看结果越快，迭代就越快。把评测做好，其实是个相当难的问题。”

他们的早期客户基本都是 AI 工程的先行者，这些坑自己全踩过，其中不少人在接触 Braintrust 之前已经造过一版内部工具。还有一层原因来自 Zapier 的 Brian。Brian 拿 Vercel 的文档举例：新工程师照着文档写 UI，自然就学会了构建 Web 应用的正确姿势，AI 也可以这样。AI 会是渗透到整个组织的技术，不该是一个工程师带着单个团队看护的项目。全公司需要一套统一、标准化的做法。

Ankur 把做 AI 产品最大的痛点归结为质量的不确定性。团队兴冲冲做了个原型，几个例子上跑得好好的，发给真实用户才发现根本不行。从原型到系统性好用之间隔着一条鸿沟。Braintrust 帮客户做的事，就是把这条鸿沟变成可以一步步填平的流程：写好评测，转动摇柄，把输出质量磨上去。

Sarah 补充了一个观察：早期公司的路径几乎一模一样。先研究微调或开源模型，最后发现直接用 GPT-4 就行；然后自己造内部工具，最后发现重心应该放在产品上。早期客户电话里说“我们不需要这个”，三个月后打回来：“我们真的需要。”时间点都差不多。

一半用例在跑 RAG，微调几乎全军撤退

Sarah 问出了很多人关心的问题：微调、RAG（检索增强生成）、Agent，这些被聊烂了的词，一线公司到底在用哪些？

RAG 没有悬念。Braintrust 看到的生产用例里，大约一半涉及某种形式的 RAG。简单，直接，有效。

微调的故事就曲折了。Ankur 说，很多人把微调当成一个结果，它其实是一种技术。大家真正想要的结果，是让工作负载自动优化，微调只是路径之一，而且是一条特别难走的路。

Braintrust 大约每两三个月就帮客户把微调重新测一遍。GPT-3.5 微调刚出来那会儿，GPT-4 一票难求，微调是某些用例提升质量的唯一杠杆。现在跑 GPT-4o 已经便宜到几乎不用犹豫，情况彻底变了。几乎所有客户都从微调模型迁到了指令调优模型，效果还很好。

两个概念的区别，Ankur 打了个比方：指令调优和微调的差距，大概相当于写 Python 代码和造 FPGA。指令调优，就是在 prompt（提示词）里塞例子，告诉模型该怎么表现；微调是直接改模型权重，层级低得多，更慢、更贵，还很容易把模型改伤，在真实场景里反而变差。

讽刺的是，Braintrust 最早规划功能时，头一个想到的就是帮大家微调模型。结果用他的原话说，没人真的在做这件事。

开源模型这边，他的判断是：分水岭时刻快到了，但还没到。Anthropic 的 Claude 3 发布时有过这样一个时刻，Claude 3.5 Sonnet 更是彻底起飞。Llama 3.1 很接近了，但生产环境的实际采用还非常有限，尽管兴趣比以往任何时候都高。

他自己就是开源爱好者，每次按 token 付费都肉疼。但他看了客户的账本：不少场景下 API 费用便宜到可以忽略，真正花钱的场景投入产出比又很高。客户关心两件事：给用户最好的体验，给开发者最快的迭代速度。开源模型在这两根轴上撬不动指针，就很难被大规模采用。

自由式 Agent 正在被一线公司悄悄放弃

走完一年到一年半 LLM 旅程的公司，现在都在干什么？Ankur 的答案可能是整期播客里信息量最大的部分。

这些公司一般已经有一两个成熟的明星产品，正在琢磨怎么推到下一阶段。而它们最一致的动作是：从“全自由 Agent 能解决一切”的幻觉里退出来。

两三个月前，一批先锋公司一头扎进 Agent 的兔子洞，然后发现不对劲：性能太难控制，错误率本来就高，还会快速叠加，Agent 每多走一步，出错概率都在滚雪球。

于是这些公司往回走，换了一种架构：控制流由代码确定性地管理，LLM 调用散布在产品的整个架构里。Ankur 说这东西还没有统一的名字，大概是“贯穿产品的普遍性 AI 工程”：LLM 用在产品各处，Agent 的野生循环则被搁到了一边。

团队组织也在跟着变。ChatGPT 发布到现在快两年，最早吃螃蟹的那批公司里，很多根本没有机器学习团队，一张白纸，反而跑得飞快。传统的 ML 工程师和数据科学家早期普遍抵触，觉得 LLM 解决不了他们的问题，甚至有人觉得这是个骗局。

Ankur 对此很有共鸣，因为他自己就是这么过来的：Impira 那套文档提取技术，眼看着变得毫无意义。他的判断是，这基本是个情绪问题。第一次用 GPT-3 的人会发现它还有点阴阳怪气，关键是它什么都比你自己辛苦训练的模型强。对做了多年 AI 和 ML 的人，这是对个人身份的根本性冲击。

现在，聪明的 ML 人陆续转身，把评测、度量、原型这些依然有效的严谨方法带进 LLM 世界，组成新的 AI 平台团队：产品工程师打底，配几个统计和数据科学背景的人。路径通常是先做出公司的招牌 AI 产品，再演化成平台团队，让第 N+1 个项目直接站在他们的肩膀上。

传统企业现在想入场，该招什么人？Ankur 的答案：先招一批聪明的产品工程师。第一个要问的问题是，我的产品里哪些部分会被现代 AI 吞掉或者彻底改变，产品工程师最适合想这个问题。一个好 UI 加上很基础的 AI 工程，就足以验证概念。Vercel 的 v0 现在是工程杰作，早期其实相当简单。等找到产品市场契合，再上严谨性、微调、开源模型降本，顺序别搞反。

TypeScript 成了 AI 的语言，数据仓库的剧本要重写

Ankur 有个说法：Python 是机器学习的语言，TypeScript 是 AI 的语言。

数据支持这个判断。Braintrust 的客户绝大多数用 TypeScript，连那些以前主力写 Python 的团队也换了。原因有两条。第一，TypeScript 是产品工程的语言，而驱动这波 AI 应用创新的正是产品工程师，他们把整个 AI 生态拽进了自己的世界。第二，TypeScript 的类型系统天生适合 AI 工作负载，类型系统能把模型吐出来的那些疯疯癫癫的输出，洗成结构清晰的数据，再喂给系统其余部分。处理不确定形状的数据，TypeScript 就是更合适，Python 的类型系统还太嫩。

过去半年他看到的最大变化，是大家在抛弃框架。早期人们觉得 AI 像当年的 Ruby on Rails，需要新框架才能写新应用。现在想明白了，AI 就是软件工程的一部分，正在渗透进整个代码库，不会被任何单一框架圈住。

供应商也在收敛，背后推手是 AWS。Anthropic 进了 Bedrock 之后，AWS 找回了状态，Claude 3 和 3.5 又确实能打。Ankur 见过最极端的案例：一家公司的 AI 供应商清单上只剩 OpenAI、AWS 和 Braintrust，其他全被收敛掉了。他的提醒很直接：别低估 AWS 和超大规模云厂商，尤其在基础设施这一层。

数据库老兵谈数据基础设施，视角又不一样。过去企业把大量半有用数据囤在数据仓库里，LLM 出现之前还有一整条产业围绕这件事，DataRobot 这类公司帮你用仓库里的私有结构化数据训练模型。LLM 带来的最疯狂的认知冲击是：一个在互联网上训练出来的模型，性能超过了企业用自己仓库数据训练出来的一切。

数据的价值逻辑跟着变了。囤理赔记录、交易记录，可能根本没那么有用，真正的问题是构建一个擅长推理你所关心问题的模型。一个细节：客户通过日志存进 Braintrust 的数据，很多永远不会进数据仓库，大家不在乎，因为存进去也不知道能干嘛。

数据仓库的设计目标是对结构化数据做即席探索，用 SQL 查询。AI 的世界两样都不沾：处理的是海量文本，探索方式也不是写 SQL。最先进的公司在用 embedding（向量嵌入）和模型本身筛数据，比如从几百万条客服工单里，找出评测数据集没覆盖到的那些例子。

他的预言：LLM 和 embedding 会成为人们查询数据的核心方式，取代传统的代数关系索引。至于吵得沸沸扬扬的向量数据库之争，他觉得挺无聊，关系型数据库加个 HNSW 索引就完事了。真正会被颠覆的是 OLAP 负载。语义搜索没法硬塞进传统数据仓库的架构，这比 OLTP 那边的改动深刻得多。

第三次创业：把公司围着长处设计

这是 Ankur 的第三次创业，有些东西他从 SingleStore 带过来了。

第一件是高难度的技术面试。MemSQL 当年以技术强度著称，他创业第一件事就是和 Manu 花了两三天打磨面试题。Braintrust 的前端面试里有一道题要写 C++，因此吓跑很多候选人。他觉得这是好信号：他们要的就是愿意在陌生技术栈里跳来跳去的人。

第二件是对客户的痴迷，但加了纪律。十个客户提十种需求怎么办？Braintrust 的做法是刻意挑客户。他们假设 Zapier、Notion 这类公司用例相似，那么这些客户提的需求，同类客户大概率也需要。这样既以客户为中心，产品又能复制。现在下一波做 AI 的公司想把自己工程成他们最佩服的那些产品的样子，而那些产品大多在用 Braintrust，最佳实践已经被打包进产品里开箱即用。

获客打法来自 Elad 的真传。他们列了一份50人的名单，选出他们认为引领 AI 方向的人，想办法把这些人变成投资人或者客户。有人投了钱但不用产品，说“我们自己已经造了轮子，不过别人会需要的”，这些人后来大多也成了用户。50家公司听起来市场很小，但它们极具影响力，带来了后面无数客户。Elad 补充，很多创业者死于初始客户包定义错误：要么从财富500强到小初创全都要，要么钻进一个不值得做的细分。

还有一件反常规的事：他这个 CEO 大量时间在写代码。他的解释分两层。市场变了，企业软件的买家在意 UI 的精致程度，Notion 养刁了大家的胃口，而很多 VC 形成认知的年代，是企业 IT 拿着产品经理的清单采购。他自己这一层更简单：试了十几年戒不掉，写代码是他参与公司最快、最高效、也最愉快的方式。所以他反过来把公司设计成支持他写代码的样子，最早招的 Albert 之前是投资人兼投行家，销售、市场、运营、招聘一把抓，把他在 Impira 时要花掉一半以上工作日的事全接走了。

Sarah 提到黄仁勋上节目说过类似的话：围绕 CEO 的长处来设计公司，别每次都套同一个模板。当然有例外，销售提成这种东西就别发明了，第一次创业的人都试过，第二次创业就老实了。

最后两条纪律：全员到办公室，习惯被打断。这两仗在 Impira 没打赢，因为态度不够坚决。Braintrust 的规矩是，客户抱怨什么、嫌 UI 哪里碍眼、提个点子，几乎总是立刻修。很多工程师受不了这种节奏，但对的工程师一辈子都在渴望这种体验，他们专门挑这种人。每家公司不必有同样的棱角，但必须得有棱角。

评测的尽头，是 AI 评 AI

Braintrust 的产品边界一直在被客户推着走。最早只做评测，Airtable 早期的做法让他们看到了下一步：每天创建一个“实验”，把线上日志当评测数据往里倒，硬是把评测产品用成了可观测性工具。Ankur 团队去问为什么，答案很清楚：AI 产品的可观测性，目的就是收集数据、攒成数据集，供评测和后续优化用。两件事本来就是一件事。

接着客户又提要求：我天天泡在 Braintrust 里做评测看日志，为什么还要回到 IDE 里写 prompt？那个 IDE 既不了解我的评测，也不了解我的日志。能不能直接在 Braintrust 里改 prompt、复现线上问题、保存之后自动部署到生产环境？Ankur 承认，从老派工程师的角度看，自动部署 prompt 这件事把他吓得不轻，但客户要，就得给。他提到一位刚成为 Braintrust 日活用户的资深工程师，现在每天有一半时间泡在里面调 prompt。

他给 Braintrust 的未来画了张图：有点像 GitHub，在产品里创建 prompt，用 Python 和 TypeScript 代码写更复杂的功能，和 prompt 缝在一起，一路打通评测和可观测性，做成 AI 的通用开发者平台。

至于质量问题会不会哪天消失，他经历过前 LLM 时代，答案是：焦虑的剧本一模一样。当年做文档提取，所有人都说六个月内文档会被完美提取，LLM 都这么强了，文档提取到今天也没被彻底解决。人们总会把手头的技术推到极限，AutoGPT 就是这样一个有益的实验，推过了技术能合理承受的范围。AI 本质上是非确定性的，评测会一直在，只是评的对象越来越复杂。

那 AI 会不会接管评测本身？Ankur 说这已经发生了。道理和数学一样，验证一个证明比生成一个证明容易得多，前沿模型看另一个模型的产出，能给出准确的评价。Braintrust 上超过一半的评测已经是 LLM 在评。

更新的玩法是拿 LLM 评日志：写好基于 LLM 和代码的评估器，自动跑在线上日志的抽样上。这里有个巧妙的解锁，有些数据人类员工按规矩不能看，LLM 可以读 PII（个人身份信息），替你判断线上用例是否正常工作。让模型看人不能看的数据，评人评不了的系统，这大概就是未来一年评测的形态。

最后，把 Ankur 这期里能直接抄作业的东西收拢一下：

  • 上线任何 AI 功能前，先攒评测集，十几条真实案例也行。原型能跑和系统性好用之间的鸿沟，只能靠评测填。
  • 想提升效果，先在 prompt 里塞例子，别急着动模型权重。一线公司每两三个月重测一次微调，结论几乎都是不值得。
  • 已经上了 Agent 的，检查错误率怎么叠加。更稳的架构是把控制流收回代码，让 LLM 调用散布在产品各处。
  • 用类型系统接住模型输出，把不确定性关进结构里，TypeScript 在这件事上比 Python 好用。
  • 做开发者产品的，学这份冷启动名单：找出50个最有影响力的潜在用户，把他们变成投资人或客户。
