《100 张 GPU 几秒到手：Modal 创始人把云计算重做了一遍》

训练一个大模型，要动用一整个数据中心的 GPU，让这台超级计算机连跑几个月，最后的产出是一个文件。No Priors 主持人 Sarah Guo 在节目里把这个事实摆出来时补了一句：仔细想想，挺疯狂的。这个文件某种意义上是整个互联网、一整个人类知识语料库的压缩表示。

接话的人叫 Erik Bernhardsson，Modal 的创始人兼 CEO。Modal 做的是面向 AI、机器学习和数据应用的 serverless 云平台，客户里最有名的例子是 AI 音乐公司 Suno，它的全部推理都跑在 Modal 上，规模非常大。Erik 给出的承诺听着很直白：客户需要一百张 GPU，通常几秒之内就能到位。

他的履历也不复杂：2008 年加入 Spotify，待了七年，带队搭起音乐推荐系统；后来去房产科技公司 Better 当 CTO；疫情期间休假写代码，写着写着决定创业。这期节目基本围绕一个问题展开：AI 时代的云计算，到底哪里用着难受，该怎么重做。

在 Spotify 造了七年轮子

2008 年的 Spotify，数据基础设施接近荒地，最时髦的工具还是 Hadoop。想做推荐系统，只能自己造。Erik 写了个工作流调度器叫 Luigi，又造了一个向量检索库，就是后来在开源圈流传很广的 Annoy。他的自我评价带着自嘲：这些工具当年都有人用，如今基本退出了舞台中央。

七年下来他攒出一个判断：做 AI 和数据应用，工程师大部分时间耗在基础设施上。后来在 Better 当 CTO，他天天琢磨的是开发者效率。疫情期间休假，动手写了些原型，很快确认方向：给数据、AI、机器学习造一套更好的基础设施，这就是他想干的事。

他想清楚的核心体验是：让云端开发的手感接近本地开发，反馈循环要快，代码写完立刻能跑，不用等环境配置。为此他做了个激进决定，Docker 和 Kubernetes 直接扔掉。Modal 头两年基本都在铺地基：自研文件系统、自研调度器、自研容器运行时，就为了让容器冷启动足够快，让用户的自定义代码能安全跑在自家基础设施上。Erik 承认这是硬骨头，容器化并安全运行用户代码，是比只做推理或只服务大语言模型难得多的通用问题。

产品形态说起来很简单：客户用 Python 写函数，Modal 把这些函数变成云上的 serverless 函数，容器化、调度、扩缩容全包了，Kubernetes 和 Docker 那套东西客户碰都不用碰。公司创立时生成式 AI 还没爆发，第一批真正带火 Modal 的需求来得有点意外：Stable Diffusion 发布，一群人涌过来说，你们这里有 GPU，又不用自己开机配机器，正合适。文生图至今仍是大头，音频、音乐、视频的用量也都在涨。

买 CPU 按秒，买 GPU 却要签长约

Erik 在 2024 年 10 月写过一篇文章，标题大意是「AI 的未来需要更灵活的 GPU 容量」。他指出的悖论很扎眼：GPU 越贵越稀缺，获取它的主流方式越是签长期合约，而这种模式恰恰最不适合创业公司。

云计算当初迷住他的地方，就是要多少 CPU 点一下就有，他从 2009 年前后就开始用云。GPU 因为供给紧张，过去几年想拿到货，基本得签一两年甚至更长的合同。他的愿景一句话说完：GPU 应该像 CPU 一样随取随用。

推理场景把这个问题放得最大。训练好歹能提前算出要多少卡，推理的用量事先根本估不出来，波动极大。容量规划于是变成两难：多备了，钱烧在闲置的卡上；备少了，流量高峰一来，服务质量直接崩。

Modal 的解法是把所有客户的负载汇进一个多租户大池子，几千张 GPU 跨客户共享，按容器实际运行的时间计费，容器停了就不收钱。客户不用做容量规划，不用预订资源。Erik 说，那些特别突发、特别难预测的负载，恰恰是这套模式最擅长的，而多租户带来的容量管理优势，正是它能做到秒级分出几百张卡的原因。

训练这块他划了条界线：Modal 传统强项是推理，现在也接短平快、突发性的实验性训练，那种超大集群连跑数月的训练是另一个市场，不碰。更大的野心是端到端。他的目标客户是传统 ML 工程师，就是自己造模型的那群人，整条生命周期都想覆盖：数据预处理、训练、推理，再加上回收数据、在线排序模型这类反馈闭环，还有数据管道、每晚跑的批处理任务。现状已经有个有趣现象：Modal 还没出训练产品，不少客户已经拿它做批量预处理，比如训练视频模型的团队，把几个 PB 的视频丢上来做特征抽取，训完别处，再回到 Modal 做推理。

他还提了个自己很期待的基础设施方向：现在要高效训练大模型，得砸重金铺 InfiniBand 这类高速网络，把 GPU 关进巨型数据中心。如果训练能变得不那么吃带宽，跨数据中心拼 GPU 就会成为可能，整个训练基础设施都会跟着变。

大企业为什么该放心把算力交给别人

Sarah 替企业客户抛出顾虑：数据已经放在 AWS、GCP 或 Azure 上，应用在上面跑，云市场积分也买了，安全审查也过了，他们担心把活儿交给第三方平台，会引入延迟和安全风险。

Erik 的回应方式是搬历史。2008、2009 年云刚出现时，他的第一反应是：谁会把计算放在别人的电脑上跑？这不是疯了吗。几年后他改了主意，如今连大企业都承认，机器放在大云厂商手里，可能比自己机房更安全。

第二个参照是 Snowflake。2012 年前后他跟 Snowflake 的人聊过，对方的路线是直接在云上跑数据库，不部署进客户自己的环境。他当时觉得这想法疯了。现在 Snowflake 是一家规模很大的上市公司，用事实证明了基础设施即服务这条路走得通。

他判断多租户模式的顺风正在积累：安全正从网络层转向应用层，带宽成本在下降，还有各种压低传输成本的技巧，比如把数据放进 Cloudflare R2 这种零出口费的存储。他的结论是：AI 未来很重要的一部分，就是运营一个巨大的算力池，然后非常动态地把它切分给所有人。

什么时候必须自己训模型

Sarah 问了个很多团队都纠结的问题：用现成模型，还是自己训？Erik 的答案分两层。

第一层，只要模型质量是公司的核心竞争力，长期看就必须自己训。理由很朴素：不训自己的模型，护城河在哪里？你总得在技术栈的别处找到一条护城河，这当然可行，但如果你自己的模型明确比所有人都好，模型本身就是护城河。

第二层，LLM 领域之外这件事更清楚。做音频、视频、图像模型的团队，如果这是核心业务，自己训模型基本没有商量余地。这条判断对创业公司尤其重要，模型之外的机会同样真实存在，关键是想清楚护城河放在哪一格。

聊到基础设施还缺什么，他先开了个玩笑：

「我肯定有偏见，但我觉得这个世界上缺的就是 Modal，缺一种让工程师把代码拿来就能跑的方式。」

认真的版本是：在 LLM 之外，大量团队想训练自己的模型、跑自己的模型、搭高度定制的工作流，而这件事至今仍然很痛苦。存储侧他也在关注向量数据库的演化。圈子里吵个不停的话题是向量数据库该独立建，还是直接用 Postgres 加 pgvector，他的态度是，很多东西塞进关系型数据库确实够用，但他真正感兴趣的问题在更远处：AI 原生的数据存储，未必长着数据库这张脸。

他给了个具体设想：数据库本身成为嵌入引擎。现在的模式是把向量放进去，按向量搜；更原生的做法是直接放文本、放视频、放图片进去，然后按这些东西搜。他承认这话说出来有点飘，但坚持一点：这个领域太早了，大概要五到十年才能定型，现在的争论可能都发生在过渡形态上。

效率涨十倍，工程师反而更多

Erik 是国际信息学奥林匹克（IOI）金牌得主，高中还拿过瑞典物理竞赛冠军，标准的数学竞赛少年。Sarah 问他 AI 会怎么改变编程，有没有反直觉的预测。

他的回答一点也不算反直觉，甚至有点泼冷水：AI 只是开发者效率长跑中的又一棒。前面已经有编译器、高级语言、数据库、云计算，回头看，AI 未必比其中任何一次更特殊。

关键在他后面讲的这条规律：每一次效率跃升，软件的潜在需求都大得惊人，结果工程师总数反而上涨。从汇编到高级语言，从单机到云，每一步都有人预言程序员要过剩，每一步之后岗位都变多了。他给了个粗略刻度：过去四十年，工程师的生产力大约每十年涨十倍，靠更好的框架、更好的工具，而效率解锁的是更多此前做不起的软件需求。所以他非常看好软件工程师这个职业，认为要摧毁这种需求得费极大力气。AI 在他眼里干的事，是解锁了更多潜在需求。

音乐、天气和显微镜

聊到值得关注的开源模型，Erik 说风向有点变化，受关注的更多是 Flux 这类由商业公司开放权重的图像模型。他个人最惦记的是音频，认为音频被探索得太少，开源模型在那里机会很大，只是还没出现真正惊艳的东西。

带着 Spotify 的旧背景，他毫不掩饰对 Suno 的兴奋。Sarah 提到 Suno 公开聊过自家模型用了 transformer 骨干，Erik 的印象是扩散和 transformer 两条路线都在用，具体配比他不确定。AI 生成的音乐现在还能听出不对劲，有点恐怖谷，但 Suno 每一代模型都在明显变好。他还给音乐这个品类定了个性：每次新技术出现，音乐总是最早显出真实冲击力的领域之一，留声机、盗版、iTunes、Spotify 都是这样。而 Suno 更特殊的地方在于，这种产品在生成式 AI 出现之前根本不可能存在，五年前它没有生存空间。

科学计算是他点名的另一片洼地。物理学的黄金年代是上世纪二十到四十年代，之后这个领域在他看来进化缓慢，甚至有点沿着威滕那条理论路径走得太深。Sarah 把话题拉回工程侧：她指的是 ANSYS 那类用计算模拟机翼、模拟承重结构的高性能计算。Erik 承认 HPC 一直存在，石油天然气行业用了几十年，但那是一堆为具体场景手工调参的小模型，真正需要的是重做一遍。

他点名了几个深度学习应该能啃下来的方向：气象预报，尤其是湍流预测，传统物理方程解湍流非常吃力，英伟达和谷歌的团队已经发了些有意思的论文；还有生物技术，蛋白质折叠、序列比对已经证明了计算方法的威力，他感觉计算生物学正在复兴，Modal 上相关用量也在涨。

具体用例里他提得最多的是医学影像：用现代方法自动化处理上百万个实验，做自动化电子显微镜成像，再把海量图像放到 Modal 上做处理和计算机视觉。他自嘲不是生物背景出身，这只是从客户名单上看到的观察，但觉得这个方向很酷。

这期节目信息量不小，收拢成三个明天就能核对的问题：

  • 签 GPU 长约之前，先算用量波动。把过去几个月推理用量的峰值和谷值拉出来看一眼，如果波动超过几倍，按需付费加多租户平台大概率比包年包月划算，还顺手解决了容量规划的两难。
  • 问自己一句：模型质量是不是我的核心竞争力。是，就尽早攒数据自己训；不是，就把护城河明确放到别处，比如数据、分发、产品体验，别为了训模型而训模型。
  • 存储选型别过度纠结。向量数据库还是 Postgres 加 pgvector，按 Erik 的说法，现有方案里塞进关系型数据库多数够用，AI 原生存储还要五到十年才定型，现在把时间花在产品和数据上更值。

至于工程师要不要担心被 AI 取代，答案藏在那条四十年的规律里：效率每十年涨十倍，需求跟着涨。工具越好，能做的东西越多。这是 Erik 下注的方向，也可能是每个写代码的人该有的底气。
