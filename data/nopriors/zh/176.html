《Google 花1000万美元买走破产航司的数据，Eon 创始人把数据护城河讲透了》

2026年8月，Spirit Airlines 走破产程序，Google 从清算资产里挑了一样东西。飞机没要，航线没要，只花了1000万美元，把这家航空公司的数据整个买走，拿去训练模型。主持人还补了一句传闻：竞价名单上的对手，是 AI 公司 Mercor。

一家破产航司的内部数据，两家 AI 公司抢着出价。这个细节比1000万美元本身更有信息量。

No Priors 这一集请到的嘉宾，是数据公司 Eon 的两位联合创始人 Ofir Ehrlich 和 Gonen Stein。Eon 做云备份和灾难恢复，听起来像门老生意，两位创始人上一家公司 CloudEndure 卖给了 AWS。Eon 现在的产品逻辑是：帮客户把散落在多家云厂商的数据做映射和分类，识别有什么、在哪、哪些敏感，再把结构化和非结构化数据摄取进一个统一的数据底座，这个底座既能做备份和恢复，又能直接跑查询、搜索和 AI 模型。这一集聊下来，几乎每一段都指向同一个判断：模型和算力人人买得到，企业真正带不走、抄不走的资产，只剩数据。

模型会过时，数据不会

Ofir 的逻辑很直接：模型、算力这些基础设施当然重要，但它们几乎是易耗品，切换成本接近零，今天用这家模型，明天换那家，一个下午的事。酒店连锁、餐饮连锁、科技公司，不管做什么生意，手里最值钱的是数据。

Spirit Airlines 的数据为什么值钱？Gonen 拆成了两层。第一层，它是一家航空公司的完整运营记录，Google 本来就在做旅行相关业务，买回去能继续训练、继续变现。第二层，它是一家大型企业的运作样本：中层管理怎么协作，审批怎么走，问题怎么处理，这类数据市面上几乎买不到。

这里有个关键背景。Gonen 说，现在做 agent，光靠实验室的数据不够，训练数据得像真实世界。Hugging Face 前几天刚发布了一个法律数据集，但市面上像样的真实企业数据集很少，大部分合成数据一看就假。公开数据教不会模型「一家公司是怎么运转的」，只有真实企业的内部数据能做到。所以 agent 公司现在要么去客户现场拿数据，要么直接买。

趋势已经起来了。Ofir 说，有实验室的人跑去华尔街，找对冲基金买数据，想搞懂怎么映射和分析公司。做技术数据的 CEO 现在经常被问同一个问题：你的数据卖不卖？那些在公司货架上落灰多年的老数据，突然成了抢手货。

主持人补了一个视角：「数据是新石油」这话讲了十年，他一直持怀疑态度。现在情况变了，后训练和强化学习让企业专有数据真的能喂进模型，Applied Computing 这类公司专门提供针对企业数据集微调模型的服务。数据第一次有了清晰的变现路径。

数据都在，就是拿不出来

Eon 的生意要从一个问题讲起：企业的数据明明都在自己手里，为什么用不上？

Gonen 在节目里还原了一个典型场景。数据团队负责人被 CEO 叫去，CEO 和董事会刚意识到 AI 是真的，公司有那么多数据，得想办法激活。数据负责人心想，这事我熟，硅谷每天冒出来的新工具我都门儿清。

然后他卡住了。数据在哪？

数据散落在各个业务单元手里。某位业务负责人手底下几十号人，系统用了20年，有些系统没人说得清是干嘛的，里面躺着生产数据，含敏感信息。Gonen 的描述很生动：每家公司都有那么一台服务器，没人知道它在干什么，但它连着电，谁也不敢关，因为不知道里面有什么。

就算业务负责人愿意配合，把数据挖出来还要调工程师，可能要牺牲安全、合规和生产系统的正常运行，最后把数据存到一个低效的地方。两边的激励完全错位：数据团队的任务是拿到数据，业务负责人的任务是保证系统别出事，别把 CEO 的工资单不小心喂进别人的训练集。

Eon 的方案分三步，主持人在节目里总结过：第一，把客户散落在多家云厂商的历史数据和当前数据聚合起来，做映射和分类，打上上下文标签，建语义层；第二，自动脱敏和权限控制，PII、财务信息这些敏感字段要么遮掉，要么设门槛；第三，接进 AI 工作流，让模型直接能用。整个过程不碰生产系统，留全量审计。

Ofir 点出了一个讽刺的事实：客户本来就有这些数据，只是它们被锁着，访问起来又贵又慢。Eon 做的事，是把锁着的存量数据变成能用的格式，顺便把存储成本降下来。

威胁换了主角，从人变成了 agent

两位创始人聊安全的部分，可能是全集信息密度最高的段落。

先讲他们在 AWS 时期吃过的亏。当时有个超大客户被勒索软件打穿。客户用的是 AWS 托管的灾难恢复服务，双方都以为保护到位了。事后发现，客户没做资源映射、分类和打标，该保护的资源根本不在保护范围内，60% 的环境被勒索软件加密。Ofir 说，这是他们后来出来创办 Eon 的直接原因之一。备份不等于保护，没盘点、没打标的备份，关键时刻是空的。

现在威胁模型变了。Ofir 的原话：过去的威胁来自人类，现在的同类威胁来自非人类行为者，AI agent 拿着合法权限访问数据库，然后某张表突然被删掉。检测方法跟防勒索软件类似，盯异常写入模式和熵变化，但速度完全不在一个量级。

他给了一个时间线：六个月前，没人跟他聊这个话题。几个月前，他见到的每一位公司高管，要么怕这事发生在自己身上，要么已经亲身经历过。

应对思路也得跟着变：安全团队要按「已被攻破」来设计系统，不管破坏来自恶意攻击，还是来自自家 agent 的误操作。

Gonen 补充了企业侧的乱象。CIO 现在两头受气：董事会和 CEO 催着「赶紧把 AI 用起来，别拦着我」，安全上又实在吓人。非技术员工用 Lovable 这类工具给自己做应用，顺手把公司数据传上去，安全、合规、数据会被谁用，统统没概念。他们搭的 agent 还会调用别的 agent，比如 OpenClaw 连着 WhatsApp，又连着公司内网和各种应用。

组织内部凭空多出了一整套行为者，他们不受组织规则约束，也未必运行在组织内部，手里却攥着组织的敏感数据。

Gonen 的评价是，组织里人人都能当建造者，社交媒体经理、财务、法务都能上手做工具，这是好事也是坏事，「我们活在一个非常有趣的时代」。

安全行业已经用脚投票。Gonen 的观察：做 NHI（非人类身份管理）的网络安全公司多到数不清，因为这个问题已经排进企业安全榜单的前两名。终端安全也在重演，agent 跑在员工笔记本上，连着内网又连着外部服务，CIO 想管都不知道从哪下手。

旧管道为什么不够用了

主持人抛了个问题：过去十年建的 ETL 和数据工程基础设施，还能撑多久？

Gonen 用买咖啡举了个例子。他下楼买杯咖啡，刷卡，这笔交易写进某个数据库。今天的处理方式是，数据被抽取出来放到某处，另一个人在另一个环节拿去加工，各干各的，中间没有联系，也没有上下文。

以前这样凑合能用，原因是数据的用途在写入那一刻就定了，你只会拿它做你本来就想做的事。现在逻辑变了：数据的价值藏在组合里。一个团队拿到足够多、足够干净、带上下文的数据，能干出以前想都不敢想的事。

他举了个更直白的例子。公司里一个人掌握纽约所有爱吃汉堡的人的名单，另一个人掌握纽约所有爱吃披萨的人的名单，两个人互不知道对方有什么，这两份数据就产生不了交集。合起来，才是一份「又爱汉堡又爱披萨」的名单，拿去做后训练、做新产品，价值完全不同。

主持人还问了一个具体问题：看板会不会消失？现有数据栈是为人类设计的，数仓、看板、ETL、BI，全围绕人提出预定义分析问题来搭，agent 的行为方式完全不同，动态、大规模、跨系统。Gonen 的答案反直觉：看板会变多，不会消失。编码 agent 已经在写世界上大部分代码，agent 还在调用其他 agent，组织里的非人类行为者多到没法逐个追问，看板成了唯一能看清它们在干什么的方式。

数据量本身也在暴涨。Ofir 说，他们和同行都看到数据摄入量涨得离谱，其中很大一部分由 agent 生成。噪音多，价值也藏在噪音里，所以需要能跨来源理解数据、清洗噪音、保证可用性的新工具。Fivetran、dbt、Monte Carlo 这些老牌工具很出色，但太垂直，各自只解决一段问题。

Databricks 被 Gonen 点名，他称它是「这个星球上最了不起的公司之一」。它的动作本身就是信号：数据进来越来越多，来源越来越散，它一边帮客户切分利用数据，一边不停重塑自己，自建 agent，自建数据库，想把数据从产生到使用的全流程握在手里。三年前没人这么用数据。

成本也是新变量。Gonen 提到，「token maxing」的时代结束了。以前流行的打法是把上下文塞满再说，现在 token 越来越贵，每一分钱都要换回对应的价值。该花的钱照花，但数据要存得高效，取得聪明。

经历过云迁移的人，怎么看这轮 AI 转型

两位创始人的独特之处，是他们完整经历过上一轮基础设施变迁。CloudEndure 时代，他们帮企业把几千、几万甚至几十万台服务器迁到 AWS、Azure、GCP，产品被 OEM 进各家控制台，公司卖给 AWS 后变成了 Application Migration Service。

Ofir 的对比结论：这轮 AI 转型是同款剧本的加强版。云迁移费时费力，技术和人的工作量都巨大。AI 这轮速度快得多，还冒出了新问题：客户失控的速度超过了获得价值的速度，失控本身成了阻力。企业因为怕系统崩、怕数据泄漏、怕 IP 外流，干脆按下暂停键。

传播路径也完全不同。Ofir 说，云这个东西很抽象，本质是「别人的电脑」，跟奶奶都解释不清。AI 不一样，ChatGPT 时刻之后，每个人都亲手体验过它能干什么。所以这轮是 CEO、董事会、股东自上而下推着走：用 AI，否则出局。

企业消费软件的方式也在变。最明显的是前置部署工程师，FDE。以前这是 Palantir 的玩法，外人看不懂，现在人人都在做。传统大企业想用 AI，但内部流程走完要一两年，等不起，只能请带着成熟 playbook 的硅谷工程师进场，替他们把组织改造了。Ofir 观察到，这类公司的销售周期在缩短，增长在加速。

Cognition 是他点名的新样本：先靠 PLG 起量，再转 FDE 模式，打进银行，用自家工程师替客户干那些客户不想干的工程活。多条路径一起吃。

还有一个更激进的玩法。有一家叫 Long Lake 的公司，思路是与其劝传统企业慢慢上 AI，直接把企业买下来，改造成 AI 公司，利润率拉高，多方共赢。

Ofir 的整体判断很冷静：大家把这轮叫革命，但大多数公司还没真正用上 AI，绝大多数还在起点。他们都隐约知道数据重要，知道现有流程低效，害怕，但不得不动。他最后说，这一程会很颠簸，但他相信世界会因此变得更好。

明天就能用上的五件事

这一集聊的是大公司的账，但里面的动作拆出来，中小团队同样用得上。

  • 做一次数据盘点。花一周时间，把公司的数据资产列清楚：在哪、谁管、什么敏感级别。Spirit 的数据能卖出1000万美元，前提是它完整、可识别。连自己有什么数据都说不清的公司，谈变现和护城河都太早。
  • 检查备份有没有打标。AWS 那个客户的教训：没映射、没分类的备份等于没备份。确认备份策略里有分类打标这一步，并且定期做恢复演练，别等勒索软件来了才第一次测试。
  • 把 agent 当员工管。每个接入公司系统的 agent 都该有独立账号、最小权限和审计日志。先问一句：现在公司里有哪些 agent 在跑，连了什么？答不上来，就是风险敞口。
  • 给非技术同事立规矩。用 Lovable、OpenClaw 这类工具做东西之前，公司数据能不能上传、传给谁，要有明文规定，不能默认靠自觉。
  • 存量数据先脱敏再谈变现。数据要喂给模型或者第三方之前，PII 和财务字段先处理，权限和审计跟上。数据是资产，裸奔的数据是负债。

这笔账其实很好算：模型会贬值，算力是租的，只有数据是你自己的。把它盘点清楚、管起来，比追任何一个新模型都值。
