《Log4j 级漏洞从一年一次变成每周一次，Cloudflare CTO 谈怎么活过这 18 个月》

先摆三个事实。过去三到六个月，CVE 漏洞报告的数量呈指数级上涨。Cloudflare 的主题演讲里给出一个判断，未来 18 个月，超过一半的工程时间会花在安全上。还有，一把本该保护全球 TLS 和 WebPKI 体系的关键密钥，生成时用的随机种子，是数字 4。

第三件事多说一句。密码学建立在随机性上，种子是 4，等于把保险箱密码设成 0000，谁都能逆向复现。讲这件事的是 Cloudflare CTO Dane Knecht，语气很平静。他说这类活现在 AI 直接就能干，模型不睡觉，不像公司里那个负责红队的工程师，到点下班。

Dane 最近上了 Sarah Guo 和 Elad Gil 主持的投资人播客 No Priors。聊的范围很广：AI 把漏洞挖掘变成了流水线，agent 上网需要一个新经济模型，还有 Cloudflare 这家 5000 人公司怎么用 AI 重写自己的内部流程。Sarah 开场问了个狠问题：有资深技术人说该把重要的东西全部物理隔离，未来一段时间没法信任互联网，关键基础设施和政府服务迟早出事，你预期会这样吗？

Dane 没那么悲观。但他承认，接下来 18 到 24 个月，全行业都在补账。

挖洞的主力换人了

Log4Shell、Shellshock 这种级别的漏洞，互联网以前大约一年撞上一次。每次 Cloudflare 全公司总动员，既要保企业客户，也要保免费用户，他们把这当成维护公共网络安全的一部分。现在，同样严重的事每周都在发生，只是很多没被公开报道。

挖洞的人也换了。Sarah 问这些攻击者是不是国家级黑客团队，Dane 的答案出人意料：很多大型漏洞出自高中生之手。Sarah 现场给这群人起了名字，agent kiddies，对应以前的脚本小子。他们以前打 CTF 夺旗赛，现在把 agent 指向某个目标领域让它自己跑，挖到洞交上去，漏洞赏金能拿到不小的金额。

国家队长年拥有的工具，不管靠 agent 还是靠人海，现在交到了大众手里。

他举了两个例子。一个是那把种子为 4 的密钥，随机性不足，注定被逆向。另一个是 OpenAI 的人用模型把 NIST 椭圆曲线当年发布时用的种子找了出来，那批曲线 2000 年前后发布，种子二十多年没人找到过。模型变强只是其中一半，另一半是工具链成熟了，人知道怎么指挥模型去找洞。门槛塌了，攻防的天平暂时倒向攻击方。

18 个月的补账期

Greg Brockman 前一周也上了这档节目，他的预测是，2027 年公司花在安全上的 token 钱会和写代码一样多。Dane 认同方向，驱动它的东西很朴素：危机感。未来 18 个月，安全支出会整体前置，进攻侧的红队和防守侧的加固都要加码。

但他不认为一半工程时间修安全会变成长期状态。AI 迟早把存量代码扫完，把大部分漏洞和偷工减料的地方找出来，到那时资源回到新功能上，软件生产力反而跳一跳。现在要补的账，按他的说法，是过去七年写出来的全部软件。

为什么不用那么悲观？他给了两个理由。第一，人类适应力强，关键时刻竞争对手会变成战友，Cloudflare 见过太多次，大家放下竞争一起保护关键基础设施。第二，过去五到十年，行业从城堡护城河式的安全转向了零信任，公司的安全假设已经从「这间机房是隔离的」变成「每台设备、每条数据流单独验证」，这套底子在风暴里更扛得住。

还有一个问题躲不开：AI 也在加速软件的生产速度，补旧账的同时，新代码还在涌出来。Dane 的答案是开发流程本身要改，安全要内建到软件和 agent 开发周期的每一步，靠事后扫描追不上产量。

修法：缩小攻击面，把规矩写进十诫

问到怎么写出更安全的软件，Dane 回到第一性原理：缩小攻击面。给漏洞留的地方越少越好，审视每一行代码，能不能简化，能不能砍。Sarah 补了个传神的细节，如今的模型天生爱堆复杂度，她经常要跟模型说，请用十分之一的复杂度再试一次。Dane 认同，早期 AI 在这件事上帮倒忙，所以人的判断仍然关键，架构得由人来设计得站得住。

再往上是工具链：形式化验证、内存安全的编程语言、内建安全机制的运行时。Cloudflare 内部做了一件更朴素的事，把十几年的 RFC 沉淀成一份叫 Codex 的文档，写清楚在 Cloudflare 怎么写安全的软件、怎么写高可用的软件，最佳实践最后浓缩成类似十诫的条目，agent 在每个评审环节都要照着执行。他形容这像工厂流水线，上游 agent 大量产出初稿，下游有人跑性能测试和安全测试，层层把关。

组织上，红队从现在的一个，扩到明年年底的四五个，分组扮演攻击方主动找洞。为什么靠加红队？先把补丁流程打磨完美不行吗？Dane 的逻辑是，流程永远可以更好，但真正逼流程进化的是压力。漏洞多到正常流程扛不住时，工程师那种「好的懒」会发挥作用，他们把补丁和扫描自动化掉，因为没有别的活法。重点放在发现侧，修补的事，人会自己找到简单的办法。

安全和新功能怎么排序？他的答案很直接：不发货就是等死。不会冻结开发去修安全，两件事都要，可能挤掉的是成本优化这类投入。用得对，AI 能让两件事同时变快。他总结得很对称：AI 一边制造着安全危机，一边也是更快解决危机的工具。

开源还是闭源模型的争论，他的立场也明确：长期看都得开源。坏人反正拿得到，头部公司也拿得到，闭源只是把最需要防护的大多数人挡在门外。

这套逻辑最后落回 Cloudflare 的老本行。去年 React 那个大漏洞爆出来时，Cloudflare 没把防护只留给买了高级防火墙的付费客户，免费用户一并生效，他们把这当成公共事业的一部分。Cloudflare 创立前，全球大约 3000 个网站用得上大规模 CDN 边缘缓存，现在是几亿个。把安全和性能民主化，本来就是这家公司的生意。

Agent 上网，需要一个新经济模型

聊完安全，话题转到 agent 流量。Dane 的观察是，agent 驱动的流量增长超过了大多数人的预期，整个互联网现在处在「混乱的中间态」：人和 agent 跑在同一条铁轨上。

问题在于网页为人设计。人会逛一个网站，看广告，参与完整的商业循环；agent 同样的时间能访问一千个页面，让它去读一个为人类节奏设计的网络，效率低，也撑不起收入。所以他的判断是，人的网和机器的网会分开，各自匹配各自的节奏和经济模型。现在那些帮 agent 翻译网页的中间层，在他看来是在白烧 token，网站自己最清楚自己的数据是什么。API 存在多年，只覆盖了互联网信息的一小角，agent 对全部信息有渴求，才去爬人的网页。

经济模型怎么建？他给了一个简单版本：像 Substack 这样的内容站，知道自己广告的千次展示收入（CPM）是多少。Agent 来读内容，自己决定读不读，愿意就按 CPM 付钱。这背后需要互联网的支付轨道，每秒百万级的小额交易。微支付喊了二十年，永远还差两年，这次他赌 agent 会把它真正推起来。

Cloudflare 已经在铺这些轨道：内容变现网关，站点放进来就能对 agent 收微交易；给 agent 发钱包；用稳定币结算。还有和 OpenAI 合作的 content signals，让 agent 不用反复全网爬取，主动获知新内容，AI 实验室省算力，站长省下被爬的基础设施账单。他特别提到 x402 协议，回到了 HTTP 规范里预留多年、从没被用过的 402 状态码，Tim Berners-Lee 当年留这个码，就是给支付准备的。

成功的标志是什么？Dane 说方向要反过来：以前站长付钱给平台，现在平台付钱给站长，覆盖基础设施成本，养活创作。上一代互联网养出了 YouTube、TikTok、X 上的创作者，这一代要把创作者数量再放大。

阻力也真实存在。Amazon 已经说不许个人购物 agent 进来。每次互联网变革都有「要杀死街边小店」的担忧，结果小店活得不错，但确实有人被甩下，所以站长的第一反应是先封锁，保住谈判筹码。Dane 觉得这是过渡期的正常反应，技术和商业模型跟上了，个人 agent 会像人一样顺畅地完成任务，甚至更顺。

1000 个实习生，和一封 300 美元的提醒邮件

Cloudflare 自己怎么用 AI？他们发布了一个叫 Cloudflare OS 的内部平台，员工每天在上面用 AI。出发点还是安全：担心客户数据和内部数据从 AI 工具里漏出去，所以员工可以随便用最新的模型和工具，但部署方式受控，数据流向可审计。对人是入职培训和 Cloudflare University，对 agent，就得把「Cloudflare 怎么做事」写成文档教给它。这个平台全建在自家开发者平台上，十年前从一个 serverless 计算原语起步，现在上面有一百多个工具，存储、数据库、Durable Objects，别人可以直接 fork 去搭自己公司的版本。

有个细节出乎意料：这个平台用得最多的用户来自市场销售和行政职能团队，比工程团队用得还多。Dane 说最大的坑是培训，把人指到一个聊天界面，等于递给他一张白纸。平台按业务设计好，数据接好，引导到位，大家很快意识到，它没打算取代我，它想让我把活干得更好。这次大会本身的物料，市场团队就造了几百个内部工具，以前这些活要外包给代理公司，现在一个小团队跑完全程。

今年 5 月 Cloudflare 做过一轮组织调整，Dane 承认很痛，送别了同事。理由是看到 AI 在改写一些团队的作业方式，必须推倒重想。他举的例子很具体：产品经理以前给客户发一封邮件，要动三个团队，去 BI 拉人群包，找市场团队把文案和口吻弄对，再让市场运营发出去。不逼一把，这种流程永远不会被重新设计。现在是一个工具搞定：产品经理描述人群包，写邮件，AI 按公司口吻重写，经理点一下批准，发送。三个团队并没有因此变快，出现的是一个新工具，产品经理多了个以前不存在的超能力。

谁来决定重构哪个流程？Dane 的答案是自下而上。公司永远有一千件想做的事，排到第 100 位的事，只要有人真有热情，都值得做。今年 1 月他们开了个邮箱别名 agency@cloudflare，你好奇某件事能不能用 AI 干，把要做的事发过去，会收到回信和写好的 skill 文件。有段时间大家以为那是全自动 AI，其实是几个实习生在人工帮同事写 skill 文件。这比请咨询公司来给全公司流程编目高明得多，让每个觉得「这事不该这么麻烦」的人自己举手。

token 花销怎么管？Dane 觉得让人类给每个任务挑模型本身就很傻，应该智能路由。现阶段是手动分工：规划用最强的前沿模型，执行交给开源模型，评审和红队再回到前沿模型。管理上不设 token 排行榜，不按用量考核，只看交付了什么。提醒机制倒是分级：单日花到 300 美元，系统发邮件问一句你知道吗；500 美元抄送经理；1000 美元直接到 VP。很少触发，而且多数人收到时挺高兴，因为之前根本没意识到自己在烧钱。

最能代表他们策略的是实习生数量。两年前约 200 个，今年招了 1000 个，对一家 5000 人的公司。两年前那批实习生是第一代完全 AI 原生的员工，把 AI 拿走，活儿基本停摆。Sarah 听到这有点惊讶，Dane 说这是好事，他们只是先伸手够 AI，就像把 Google 从我这拿走，我过去十年学东西全靠它。那批实习生带过的经理，自己用 AI 也更快。实习生要填个表，第一反应是写个提示词让 agent 生成，Dane 承认自己还经常手动干了半天，才想起来该用 AI，多数人还没长出这个本能。问到 Cloudflare 的 AI 旅程走到哪了，他的回答是，非常早期。

招聘标准因此变了吗？核心还是好奇心。生活里完全不用 AI 的人，在他那里是个挺大的红灯。他还看好滑铁卢、东北大学这类 co-op 项目出来的学生，真实工作经验比学历更能预测一个人后来的表现。

明天就能用上的七件事

  • 把「缩小攻击面」当成第一刀。让模型写完之后，再要求用十分之一的复杂度重写一遍，砍掉的每一行代码都是少一个洞。
  • 把团队的最佳实践写成 agent 能读的规范文档，学 Cloudflare 的 Codex 模式，浓缩成硬规则，塞进每个评审环节。
  • 模型分工：规划和审查交给最强的前沿模型，批量执行交给便宜的开源模型，别让人手挑模型。
  • 给团队装 token 提醒，别装配额。300 美元问一句，500 美元找经理。大多数人缺的只是知情。
  • 红队数量往上加，别只顾打磨补丁流程。压力会逼着流程自动化，发现侧才是瓶颈。
  • 招一两个 AI 原生的实习生。他们用工具的本能，会传染给整个团队。
  • 小团队没有红队，就把站点放到对免费用户也推漏洞防护的平台后面。React 级别的漏洞爆出来时，防护不该是付费功能。

Dane 在节目最后把话说得很直白，安全这场仗，AI 在两边同时出场。它把攻击的门槛降到了高中生手里，也把防御的速度提到了模型不睡觉的节奏。接下来 18 个月，拼的只是谁先用上它。
